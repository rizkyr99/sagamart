These conventions apply to every service, whatever its language. Their purpose is that a request can be followed, debugged and reasoned about the same way in NestJS, Java and Go. Deviations need an ADR.

## 1. Repository layout

│   ├── pull_request_template.md

├── apps/

│   ├── gateway/              # NestJS

## 2. Naming

| Thing | Convention | Example |
|---|---|---|
| Service names | lowercase, hyphenated | `event-workers` |
| REST paths | plural nouns, kebab-case, versioned | `/v1/orders/{orderId}/line-items` |
| JSON fields | `camelCase` | `orderId`, `createdAt` |
| Database tables/columns | `snake_case`, plural tables | `order_lines.unit_price` |
| Event types | `<context>.<past-tense-verb>` for the context's main aggregate, else `<context>.<entity>.<past-tense-verb>` | `order.confirmed`, `payment.succeeded`, `inventory.reservation.expired`, `catalog.product.updated` |
| Topics | `<context>.events` | `order.events` |
| gRPC services | `<Context>Service`, verb-first RPCs | `InventoryService.ReserveStock` |
| Environment variables | `SCREAMING_SNAKE`, service prefix | `INVENTORY_DB_URL` |
| Metrics | `sagamart_<service>_<name>_<unit>` | `sagamart_inventory_reservations_total` |

## 3. Identifiers, time and money

- **IDs:** UUIDv7 everywhere (time-ordered, index-friendly). Generated by the service that owns the entity.
- **Time:** stored and transmitted in UTC, formatted RFC 3339 (`2026-10-21T01:23:45.678Z`). Convert to WIB only in the UI.
- **Money:** integer IDR (`BIGINT` / `int64` / `long`) plus a `currency` field (`"IDR"`). Never floats.

## 4. HTTP APIs

- **Versioning:** major version in the path (`/v1`). Additive changes don't bump the version; breaking changes do.
- **Pagination:** cursor-based. Request `?limit=20&cursor=<opaque>`; response includes `nextCursor` (null at the end).
- **Idempotency:** every non-GET endpoint that creates or charges accepts an `Idempotency-Key` header. The server stores the key with the response for 24 hours and replays the stored response on retry.
- **Errors:** RFC 9457 Problem Details, `Content-Type: application/problem+json`.

```json
{
  "type": "https://sagamart.dev/errors/insufficient-stock",
  "title": "Insufficient stock",
  "status": 409,
  "detail": "SKU BAJU-001-M has 2 available, 5 requested.",
  "instance": "/v1/checkout",
  "code": "INSUFFICIENT_STOCK",
  "traceId": "4bf92f3577b34da6a3ce929d0e0e4736"
}
```

| Status | When |
|---|---|
| 400 | Malformed request or failed validation |
| 401 / 403 | Not authenticated / not allowed |
| 404 | Resource not found (or not visible to caller) |
| 409 | Conflict with current state (stock, version, duplicate) |
| 422 | Valid request that business rules reject |
| 429 | Rate limited (include `Retry-After`) |
| 503 | Dependency unavailable; safe to retry |

## 5. gRPC

- Definitions live in `contracts/proto/`; code is generated, never hand-written.
- Every call sets a deadline. Default 2 s for saga commands; the caller decides, the callee respects it.
- Map domain errors to gRPC status codes consistently (`FAILED_PRECONDITION` for insufficient stock, `ALREADY_EXISTS` for duplicates, `UNAVAILABLE` for retryable failures).

## 6. Events

Every event uses the same envelope (CloudEvents-compatible field names):

```json
{
  "id": "0192a7b3-...",
  "type": "order.confirmed",
  "source": "order",
  "specversion": "1.0",
  "time": "2026-10-21T01:23:45.678Z",
  "subject": "0192a7b2-...",
  "dataschema": "order.confirmed/v1",
  "traceparent": "00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01",
  "data": { "orderId": "0192a7b2-...", "totalAmount": 250000, "currency": "IDR" }
}
```

Rules:

1. **Partition key = aggregate ID** (`subject`), so events for one order or SKU stay in order.
2. **Published only through the outbox**, never directly from request handlers.
3. **Consumers are idempotent**: they record processed `id`s or rely on natural idempotency.
4. **Schema changes are additive** within a version. Removing or renaming a field means a new version (`/v2`) published alongside the old one until consumers migrate.
5. **Failed events go to a DLQ** topic `<topic>.dlq` after the retry budget (default 5 attempts, exponential backoff with jitter), with the error attached as a header.

## 7. Logging

Structured JSON to stdout, one event per line. Required fields:

| Field | Example |
|---|---|
| `ts` | `2026-10-21T01:23:45.678Z` |
| `level` | `debug` / `info` / `warn` / `error` |
| `service` | `inventory` |
| `env` | `local` |
| `version` | `0.3.1` or git SHA |
| `msg` | `reservation created` |
| `trace_id`, `span_id` | from OpenTelemetry context |

Add domain IDs as fields (`order_id`, `sku`), never interpolated into `msg`. Never log secrets, tokens, full addresses or payment details.

Libraries: `slog` (Go), `pino` via `nestjs-pino` (NestJS), Logback with a JSON encoder (Java).

## 8. Tracing and metrics

- OpenTelemetry SDK in every service; export OTLP to the collector.
- Propagate `traceparent` over HTTP, gRPC metadata and event envelopes.
- Every service exposes `/metrics` (Prometheus), `/healthz` (process alive) and `/readyz` (dependencies reachable).
- Minimum metrics: request rate, error rate and latency histogram per endpoint (RED); consumer lag, processing latency and DLQ size per consumer.

## 9. Database migrations

| Language | Tool | Location |
|---|---|---|
| Go | `golang-migrate` | `services/<name>/migrations/` |
| Java | Flyway | `src/main/resources/db/migration/` |
| NestJS | TypeORM migrations | `services/<name>/src/migrations/` |

- Migrations run automatically on service start in local and test environments, and as a separate step in deployments.
- Forward-only and backward-compatible: add before you remove (expand, migrate, contract), as described in the [development process](development-process.md#5-build).
- Migration files are never edited after they are merged; fix forward with a new migration.

## 10. Configuration and secrets

- Configuration comes from environment variables, validated at startup; fail fast on missing values.
- `.env.example` per service is committed; real `.env` files never are.
- No secrets in code, logs, images or test fixtures.

## 11. Git and code review

- **Trunk-based:** short-lived branches off `main`, merged by PR.
- **Branch names:** `feat/inventory-reservation-ttl`, `fix/...`, `docs/...`, `chore/...`.
- **Commits:** [Conventional Commits](https://www.conventionalcommits.org/) with service scope: `feat(inventory): expire reservations with min-heap`.
- **PRs:** link the issue, describe *why*, include test evidence; docs updated in the same PR.
- **Releases:** semantic versioning per service, tagged `inventory/v0.3.1`.

## 12. Language-specific style

| Language | Formatter / linter | Notes |
|---|---|---|
| Go | `gofmt`, `golangci-lint` | Standard project layout (`cmd/`, `internal/`); accept interfaces, return structs; always pass `context.Context` first |
| TypeScript | Prettier, ESLint (strict TS) | No `any`; validate input with DTOs + `class-validator` or Zod |
| Java | Spotless (google-java-format), Checkstyle | Constructor injection; records for DTOs; no field injection |
