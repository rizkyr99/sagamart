# Internal identity contract (`x-sagamart-identity`) — v1

| | |
|---|---|
| **Status** | Accepted |
| **Defined in** | [RFC-0005 §4.2](../docs/rfc/0005-catalog-cart-gateway.md#42-api-and-contract-changes) |
| **Issuer** | The gateway, only |
| **Verifiers** | Every service that receives calls from the gateway: Catalog (#27), Inventory (#17) |

The gateway authenticates the external caller (a development JWT until Core complete, then OIDC). It then tells internal services who the caller is with a short-lived token that only the gateway can sign. Services never see or parse the external token.

## Transport

| Protocol | Carried as |
|---|---|
| HTTP (Catalog) | Request header `x-sagamart-identity: <token>` |
| gRPC (Inventory) | Metadata key `x-sagamart-identity` (lowercase) |

Every internal call from the gateway carries one, including calls for guests and anonymous browsing. A service never accepts a request without it.

## Token

A JWS in compact serialization (RFC 7515), signed with **EdDSA / Ed25519** (RFC 8037).

Protected header:

```json
{ "alg": "EdDSA", "typ": "sagamart-identity+jwt", "kid": "gw-2026-10" }
```

Claims:

| Claim | Type | Rule |
|---|---|---|
| `iss` | string | Always `"gateway"` |
| `aud` | string | The **one** service the call is for: `"catalog"`, `"inventory"`, … |
| `sub` | string (UUID) | The authenticated user's ID. **Absent** for guests and anonymous calls. |
| `roles` | string array | `["buyer"]`, `["admin"]`, or `[]` for guests and anonymous calls. Unknown roles are ignored. |
| `iat` | number | Issued-at, seconds since the epoch |
| `exp` | number | `iat + 60` |
| `jti` | string (UUID) | Unique per token, for log correlation; not tracked for replay |

Example claims for an admin:

```json
{
  "iss": "gateway",
  "aud": "inventory",
  "sub": "0199f2e0-0000-7000-8000-000000000001",
  "roles": ["admin"],
  "iat": 1792574400,
  "exp": 1792574460,
  "jti": "0199f2e0-55aa-7bbb-8ccc-000000000042"
}
```

## Verification (every service)

A service **must** reject the token unless all of these hold:

1. It is a well-formed compact JWS whose header `alg` is exactly `EdDSA`. Never accept `none`, and never pick the algorithm from the token itself.
2. The signature verifies with a gateway public key the service trusts, chosen by `kid`.
3. `iss` is `"gateway"` and `aud` is this service's own name.
4. `exp` is in the future and `iat` is not in the future, each allowing **5 seconds** of clock skew.
5. `sub`, when present, is a UUID; `roles` is an array of strings.

Then authorize:

| Operation | Requires | On failure |
|---|---|---|
| Any call | A valid token | HTTP `401` `UNAUTHENTICATED` / gRPC `UNAUTHENTICATED` |
| Admin operations (Catalog `/internal/v1/admin/*`, Inventory `SetStockLevel`) | `admin` in `roles` | HTTP `403` `FORBIDDEN` / gRPC `PERMISSION_DENIED` |
| A user's cart (`user:<id>` cart key) | `sub` equals `<id>` | HTTP `403` `FORBIDDEN` |
| Saga commands (Inventory `ReserveStock`, `CommitReservation`, `ReleaseReservation`) | Defined in RFC-0002: a service identity issued to Order. Until then Inventory doesn't check these, and its gRPC port stays on the internal network. | — |

Failures are logged with the reason (never the token) and counted in `sagamart_<service>_identity_rejections_total{reason}`.

## Keys

- Keys travel as single-line environment variables: **base64 (standard alphabet) of the DER encoding**.
- The gateway holds the Ed25519 private key: `GATEWAY_IDENTITY_KEY_ID` (the `kid`) and `GATEWAY_IDENTITY_PRIVATE_KEY` (PKCS#8 DER, base64). It is never logged or shipped to other services.
- Services are configured with the public keys they trust: `<SERVICE>_IDENTITY_PUBLIC_KEYS`, a JSON object `{ "<kid>": "<SPKI DER, base64>" }`.
- **Rotation:** add the new public key to every service, switch the gateway to the new private key and `kid`, then remove the old public key after the 60-second token lifetime has passed.
- Local development keys are generated by `make identity-keys` into the git-ignored `deploy/compose/.env` (`IDENTITY_KEY_ID`, `IDENTITY_PRIVATE_KEY`, `IDENTITY_PUBLIC_KEYS`), which Compose passes to each service. Real keys never enter the repository.

## Versioning

This is version 1. Adding claims is backward compatible, and services must ignore claims they don't know. Removing or changing the meaning of a claim, or changing the algorithm, needs a new version with its own `typ` (`sagamart-identity+jwt;v=2`), accepted alongside v1 until every issuer has moved.
